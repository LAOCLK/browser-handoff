# 变更记录

## 0.5.4 — 让限流文档和代码对得上

复查 0.7.4 时发现：第 13 条写「用 lit_triage 批量就不怕限流、每篇 5–10 秒」，
但代码里下载间隔其实是 **0.4 秒**（`time.sleep(0.4)`）——0.4 秒正是触发 CPE00002 的机器节奏。

- `lit_triage.py` 新增 `--delay`（默认 5 秒），下载循环按它休眠
- gotchas 第 13 条改成与代码一致：默认 5 秒、`--delay` 可调、别调太小

## 0.5.3 — 补一条限流踩坑记录

- `docs/gotchas.md` 新增第 13 条：连续下载触发出版社限流（ScienceDirect CPE00002）
  - 现象：批量下载中途全部失败，报 CPE00002 并附 IP；等约 8 分钟恢复
  - 影响：封的是**机构 IP**，同网段其他人也会被连累
  - 解法：每篇间隔 5–10 秒、不并发；被限后立即停手；批量用 lit_triage 而不是自己写循环
  - 明确禁止：换 UA / 代理池 / 并发重试（绕过限流属违约，且封得更久）

## 0.5.2 — 先说「开窗口是预授权的」，再谈交回

实机日志（Windows 0.7.2）暴露的失败模式：检索出 50 篇订阅墙文献后，agent 只给了一张清单，
还反问「需要我把那几篇在你浏览器里逐篇打开吗？」；用户得回一句「你应该打开浏览器让我登录」，
它才真的弹窗——之后顺利拿到 32 篇。

根因不是"不会交回"，而是**把"打开窗口"当成需要征求同意的动作**，于是用报告代替了交接。

- 新增三节：开窗口是预授权的（不要问）／报告前必须先开页面／批量场景同样适用
- 硬约束：含「需要登录/订阅/付费/验证」的回复之前，必须已真实调用过 `browser_navigate`
- 附标准话术模板
- macOS 专属提醒：登录必须在 Playwright 窗口里完成，`mcp__browser__open_url` 开的窗口
  他能登录但助手接不上下文

## 0.5.1 — 把「登录墙 = 交回」写成硬约束

实测反馈：遇到需要登录的站点时，agent 会直接判"失败/无法访问"，而不是叫用户登录。

- 新增「遇到墙：先交回，再谈失败」章节：三类墙的判据、两步交回流程、四条硬性约束
- 明确禁止把登录墙说成"该网站无法访问 / 抓取失败 / 没有权限"
- 修正失败模式表里 403 那条：原来写死"换信源"，现在先判断有没有登录入口，有就交回
- 换源上限 1 个，避免 agent 用"我试了五个地方都不行"的长报告代替交回

## 0.4.9 — Windows 实测后修复

在 Windows 10 25H2 + DSH 0.2.1-rc.5 上跑完验证，修了四个问题：

- **安装重试**：DSH 运行时 `package.json.lock` 被占用会抛 EPERM，导致首次安装失败。
  现在自动重试 3 次，仍失败则明确提示「先完全退出 DSH」
- **中文乱码**：输出被重定向时 Python 用 GBK。所有脚本启动时自动切 UTF-8
- **路径分隔符**：默认下载目录由 `~` 拼接改为 `os.path.join`，不再出现 `C:\Users\x/Downloads`
- **自检临时目录**：Windows 沙盒里的 TEMP 子目录会 EPERM，改为优先用当前目录，
  并对创建失败给出可操作的提示
- 闭源文献的【需要你操作】提示改走 stdout——PowerShell 会把 stderr 渲染成红色错误
- `docs/windows-check.md` 补「已知的 Windows 坑」：python 占位符、锁、乱码、截图路径限制
